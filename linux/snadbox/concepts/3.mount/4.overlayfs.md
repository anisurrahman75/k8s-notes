## **The idea**

> OverlayFS stacks several read-only directories under one writable directory and presents the union as a single filesystem.

```
        merged/          ← what the process sees
          ▲
   ┌──────┴───────┐
   │   upper/     │      writable layer   (the container's changes)
   ├──────────────┤
   │   lower3/    │      read-only        (image layer 3)
   │   lower2/    │      read-only        (image layer 2)
   │   lower1/    │      read-only        (image layer 1)
   └──────────────┘
       work/              overlayfs scratch space (must be on the same fs as upper)
```

**That is a container image.** `docker pull` downloads the lowers; `docker run` creates a fresh `upper` + `work` and mounts the union. Ten containers from one image share the same lowers on disk and get ten tiny uppers — which is why starting a container is instant and costs almost no space.

| Directory  | Role                                                                  |
| ---------- | --------------------------------------------------------------------- |
| `lowerdir` | one or more read-only layers, **`:`-separated, leftmost = topmost**    |
| `upperdir` | the single writable layer — all changes land here                     |
| `workdir`  | internal scratch, must be empty and on the **same filesystem** as upper |
| merged     | the mount point where the union appears                               |

## **Demo: build one by hand**

Rootless overlayfs needs kernel ≥ 5.11 inside a user namespace.

```bash
S=/tmp/nslab/ovl
mkdir -p $S/{lower,upper,work,merged}
echo hello > $S/lower/f.txt

unshare -Urm bash -c "
  mount -t overlay overlay \
    -o lowerdir=$S/lower,upperdir=$S/upper,workdir=$S/work \
    $S/merged

  echo '--- read from lower:'
  cat $S/merged/f.txt

  echo '--- write through:'
  echo world >> $S/merged/f.txt

  echo '--- upper now contains:'
  ls $S/upper
  cat $S/upper/f.txt
"

echo "--- lower is UNCHANGED: $(cat $S/lower/f.txt)"
```

```
--- read from lower:
hello
--- write through:
--- upper now contains:
f.txt
hello
world
--- lower is UNCHANGED: hello
```

**Copy-up just happened.** Appending one line to `f.txt` caused overlayfs to copy the *whole file* from `lower` to `upper`, then apply the write there. The lower layer was never touched.

> ⚠️ **Copy-up is per-file and eager.** Touching one byte of a 4 GB file in an image layer copies all 4 GB into the writable layer. This is why databases and other write-heavy workloads must use a **volume**, never the container's writable layer.

## **Demo: deletions and whiteouts**

You cannot delete from a read-only lower. Overlayfs fakes it with a **whiteout** — a character device with major:minor `0:0`:

```bash
S=/tmp/nslab/ovl2
mkdir -p $S/{lower,upper,work,merged}
echo secret > $S/lower/deleteme

unshare -Urm bash -c "
  mount -t overlay overlay -o lowerdir=$S/lower,upperdir=$S/upper,workdir=$S/work $S/merged
  rm $S/merged/deleteme
  echo 'merged:'; ls -a $S/merged
"
echo 'upper:'; ls -l $S/upper
echo 'lower still has:'; ls $S/lower
```

```
merged:
.  ..
upper:
c--------- 2 anisur anisur 0, 0 Aug 11 16:31 deleteme      ← whiteout: char device 0,0
lower still has:
deleteme
```

> 🔑 **This is why `RUN rm secret.txt` in a Dockerfile does not remove the secret.** The file is still fully readable in the lower layer; only the merged view hides it. `docker save | tar -x` recovers it. Use multi-stage builds or `--secret` mounts instead.

## **Multiple lowers**

```bash
mount -t overlay overlay \
  -o lowerdir=layer3:layer2:layer1,upperdir=up,workdir=wk merged
```

**Leftmost wins.** `layer3` shadows `layer2` shadows `layer1` — exactly the semantics of successive Dockerfile instructions.

**See a real image's layers:**

```bash
docker pull alpine
docker inspect alpine --format '{{json .GraphDriver.Data}}' | jq
mount | grep overlay          # while a container is running
```

You'll see the same `lowerdir=...:...:...,upperdir=...,workdir=...` string you just typed by hand.

## **Read-only union (no upper)**

Omit `upperdir` and `workdir` for a read-only merge — useful for a truly immutable rootfs:

```bash
S=/tmp/nslab/ro; mkdir -p $S/{lower,lower2,merged}; echo x > $S/lower2/other.txt

unshare -Urm bash -c "
  mount -t overlay overlay -o lowerdir=$S/lower:$S/lower2 $S/merged
  ls $S/merged
  touch $S/merged/x
"
```

```
other.txt
touch: cannot touch '/tmp/nslab/ro/merged/x': Read-only file system
```

## **Practical notes**

| Issue | Detail |
| ----- | ------ |
| `workdir` must be empty and on the **same filesystem** as `upperdir` | otherwise `EINVAL` at mount time |
| Lower and upper on **different filesystems** is fine | lowers may even be on separate mounts |
| Hard links across the boundary don't survive copy-up | `-o index=on` mitigates |
| `overlay` on `overlay` needs `-o userxattr` in userns | rootless nesting |
| Rootless without kernel 5.11 | use **fuse-overlayfs** (Podman's fallback) |

```bash
# check your kernel supports it
grep -w overlay /proc/filesystems
uname -r
```

```
6.17.0-40-generic
```
