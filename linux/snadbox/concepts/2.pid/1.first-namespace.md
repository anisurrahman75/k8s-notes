# **1. Your First PID Namespace**

---

## **Go**

```bash
unshare -Urpf --mount-proc bash
```

Inside:

```bash
echo "I am PID $$"
ps aux
```

```
I am PID 1
USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root           1  0.0  0.0   2812  1916 ?        S    16:10   0:00 bash
root           2  0.0  0.0  13496  4556 ?        R    16:10   0:00 ps aux
```

Your `bash` is **PID 1**. The other ~690 processes on this machine still exist and still run — you simply have no name for them.

### Decoding the flags

| Flag           | Why                                                                  |
| -------------- | -------------------------------------------------------------------- |
| `-U` / `-r`    | user namespace + map you to root → lets you do the rest without sudo |
| `-p`           | `CLONE_NEWPID`                                                       |
| `-f`           | **fork** — [2.fork-rule.md](2.fork-rule.md), without it nothing works |
| `--mount-proc` | remount `/proc` — [3.mount-proc.md](3.mount-proc.md)                  |

## **Prove the isolation is real**

Still inside, try to kill a host process using its **host** PID:

```bash
kill -9 2444        # pipewire's host PID
```

```
bash: kill: (2444) - No such process
```

The host's pipewire is untouched. There simply **is no PID 2444** in this namespace — the kernel isn't refusing you, it's telling you the truth about your PID table.

Try the same with a PID that *does* exist inside:

```bash
sleep 100 &
jobs -p              # e.g. 3
kill %1              # works — it's in your namespace
```

## **Watch PIDs restart from 1**

```bash
unshare -Urpf --mount-proc bash -c '
  for i in 1 2 3; do sleep 30 & done
  ps -eo pid,comm --no-headers
  echo "--- shell is $$"
'
```

```
      1 bash
      2 sleep
      3 sleep
      4 sleep
      5 ps
--- shell is 1
```

> 💡 That trailing `echo` is not decoration. Without it, `ps` is the shell's *last* command and bash `exec`s it instead of forking — so `ps` itself becomes PID 1 and `bash` never appears. A tiny illustration of why `exec` in an entrypoint script matters ([5.reaping.md](5.reaping.md)).

Small, dense, predictable numbers — the signature of a fresh PID namespace. Meanwhile on the host those same four processes have PIDs in the hundreds of thousands.

---

## **The exit is instant and complete**

```bash
exit
```

Everything you started inside is gone — not orphaned to the host's systemd, **gone**. The kernel guarantees it. See [4.pid1-semantics.md](4.pid1-semantics.md#killing-pid-1-kills-the-namespace).

---

## **As real root, for comparison**

Without a user namespace you need actual privilege, but the result is identical:

```bash
sudo unshare -pf --mount-proc bash
echo $$        # 1
```

The `-Ur` in the rootless form is only there to *grant* you the capability. The PID isolation itself is the same code either way.
