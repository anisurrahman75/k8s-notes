## **The 3 Syscalls**

| Syscall     | What it does                                                       | CLI tool       |
| ----------- | ------------------------------------------------------------------ | -------------- |
| `clone()`   | Create a **new process** directly into new namespaces              | (runc, Docker) |
| `unshare()` | Move the **calling process** into new namespaces                   | `unshare`      |
| `setns()`   | Move the calling process into an **existing** namespace (via an fd) | `nsenter`      |

```
                 unshare()                    setns()
 host ns  ──────────────────►  new ns  ◄────────────────── another process
                                  ▲
                                  │ clone(CLONE_NEW*)
                             new process born inside
```

Real runtimes use `clone()` because it is **atomic**: the child is born already isolated, so there is no window where it exists un-isolated. `unshare` is the learning and debugging tool — it is two steps (`unshare()` then `execve()`), which is exactly why it needs a `--fork` flag.

## **Namespaces Are Files: `/proc/PID/ns/`**

```bash
ls -l /proc/self/ns/
```

```
lrwxrwxrwx 1 anisur anisur 0 Aug 11 16:10 cgroup -> cgroup:[4026531835]
lrwxrwxrwx 1 anisur anisur 0 Aug 11 16:10 ipc -> ipc:[4026531839]
lrwxrwxrwx 1 anisur anisur 0 Aug 11 16:10 mnt -> mnt:[4026531832]
lrwxrwxrwx 1 anisur anisur 0 Aug 11 16:10 net -> net:[4026531833]
lrwxrwxrwx 1 anisur anisur 0 Aug 11 16:10 pid -> pid:[4026531836]
lrwxrwxrwx 1 anisur anisur 0 Aug 11 16:10 pid_for_children -> pid:[4026531836]
lrwxrwxrwx 1 anisur anisur 0 Aug 11 16:10 time -> time:[4026531834]
lrwxrwxrwx 1 anisur anisur 0 Aug 11 16:10 time_for_children -> time:[4026531834]
lrwxrwxrwx 1 anisur anisur 0 Aug 11 16:10 user -> user:[4026531837]
lrwxrwxrwx 1 anisur anisur 0 Aug 11 16:10 uts -> uts:[4026531838]
```

Each entry is a **magic symlink**. You cannot `cat` it, but you can:

* **`readlink`** it → compare inodes to see who shares what
* **`open()`** it → get an fd to hand to `setns()` (all `nsenter` does)
* **bind-mount** it → keep the namespace alive with zero processes in it (see [4.lifetime-and-nesting.md](4.lifetime-and-nesting.md))

The number `4026531836` is the namespace's **inode**.

> 🔑 **Two processes are in the same namespace if and only if these inode numbers match.** That single fact is your entire namespace debugging toolkit.

### Why `*_for_children` exists

PID and time namespaces **cannot change for a running process** — a PID is assigned at creation and is immutable. So `unshare()`/`setns()` on those types only affect *future children*, and the kernel exposes that pending state separately:

| Symlink                   | Meaning                                     |
| ------------------------- | ------------------------------------------- |
| `pid`                     | the namespace this process is actually in   |
| `pid_for_children`        | what its next `fork()` will land in         |

Every other type applies to the calling process immediately.

## **Demo: prove two processes differ**

```bash
readlink /proc/self/ns/uts
unshare -Ur --fork --uts readlink /proc/self/ns/uts
```

```
uts:[4026531838]      ← your shell
uts:[4026533226]      ← different inode = different namespace
```

Same trick works for any type. Swap `--uts` for `--ipc`, `--net`, `-m`, `-C`.

## **`lsns` — the inventory command**

```bash
lsns                                        # every namespace on the box
lsns -t pid                                 # one type
lsns -t net -o NS,TYPE,NPROCS,PID,COMMAND   # pick columns
lsns -p $$                                  # what am I in
sudo lsns -T                                # tree view of nesting
```

```
        NS TYPE NPROCS    PID USER   COMMAND
4026531836 pid     146   2444 anisur /usr/bin/pipewire
4026535910 pid       1  24106 anisur /opt/google/chrome/chrome --type=utility ...
4026535913 pid       2  24057 anisur /opt/google/chrome/chrome --type=zygote ...
```

> 💡 Chrome sandboxes its renderers with the exact same primitives. Namespaces are not a container feature — they are a general isolation mechanism that containers happen to use.

**Reading the output:**

| Column   | Meaning                                            |
| -------- | -------------------------------------------------- |
| `NS`     | inode — the namespace's identity                   |
| `NPROCS` | how many processes are members                     |
| `PID`    | lowest PID in it (usually the namespace's "init")  |

The row with the highest `NPROCS` is almost always the **initial namespace** — the host's own.
