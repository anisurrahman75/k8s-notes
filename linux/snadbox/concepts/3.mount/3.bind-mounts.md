## **The idea**

> A bind mount makes an existing directory (or file) appear at a **second location** in the tree.

No copying, no new filesystem — the same inode, reachable by two paths. It is the mechanism behind `docker -v`, Kubernetes `volumeMounts`, ConfigMap injection, and the `/etc/resolv.conf` in every container you've ever run.

```bash
S=/tmp/nslab; mkdir -p $S/src $S/dst; echo hello > $S/src/file

unshare -Urm bash -c "
  mount --bind $S/src $S/dst
  cat $S/dst/file
  findmnt -no SOURCE,TARGET,FSTYPE --target $S/dst
"
```

```
hello
/dev/mapper/ubuntu--vg-ubuntu--lv[/tmp/nslab/src]  /tmp/nslab/dst  ext4
```

Note the source: **the same block device, subpath `/tmp/nslab/src`**. That bracket notation is how you recognise a bind mount in `findmnt`.

---

## **`--bind` vs `--rbind`**

| Flag       | Submounts under the source |
| ---------- | -------------------------- |
| `--bind`   | **not** carried over       |
| `--rbind`  | carried over recursively   |

This is a real gotcha, not a detail:

```bash
unshare -Urm bash -c "mount --bind /proc $S/dst"
```

```
mount: /tmp/nslab/dst: wrong fs type, bad option, bad superblock on /proc, ...
```

```bash
unshare -Urm bash -c "mount --rbind /proc $S/dst && echo rbind-OK"
```

```
rbind-OK
```

`/proc` has submounts. A plain bind in a **user namespace** is rejected because it would expose the parent mount while hiding what the admin mounted on top — the same locking rule from [1.first-namespace.md](1.first-namespace.md#️-you-cannot-unmount-what-you-inherited).

> **Rule of thumb:** binding a leaf directory → `--bind`. Binding anything that might have mounts under it (`/proc`, `/sys`, `/dev`, `/`, a home directory) → `--rbind`.

## **Read-only bind mounts: the two-step**

At the **syscall** level, `mount(MS_BIND | MS_RDONLY)` silently ignores `MS_RDONLY` — a bind always inherits the source's flags. Making it read-only requires a second call:

```bash
S=/tmp/nslab
unshare -Urm bash -c "
  mount --bind $S/src $S/dst                    # step 1: bind
  mount -o remount,bind,ro $S/src $S/dst        # step 2: remount read-only
  findmnt -no OPTIONS --target $S/dst
  touch $S/dst/nope
"
```

```
ro,relatime
touch: cannot touch '/tmp/nslab/dst/nope': Read-only file system
```

**Modern `mount(8)` does both steps for you.** On util-linux ≥ 2.39 (and kernels ≥ 5.12, via the atomic `mount_setattr` API) the one-liner is genuinely read-only:

```bash
mount --version | head -1
unshare -Urm bash -c "mount --bind -o ro $S/src $S/dst; findmnt -no OPTIONS --target $S/dst; touch $S/dst/x"
```

```
mount from util-linux 2.39.3 (libmount 2.39.3: ... namespaces, idmapping, ...)
ro,relatime
touch: cannot touch '/tmp/nslab/dst/x': Read-only file system
```

> ⚠️ On **older util-linux**, or when you call `mount(2)` directly from Go/C/Python, the one-step form silently gives you a **writable** mount. That is a classic container-hardening bug: the manifest says `readOnly: true`, the mount is not.

**So: never assume — verify.**

```bash
findmnt -no OPTIONS --target /your/mount | grep -qw ro && echo "really ro" || echo "NOT ro"
```

## **Bind-mounting a single file**

Works, and is how config injection is done:

```bash
S=/tmp/nslab; echo "nameserver 1.1.1.1" > $S/resolv.conf
unshare -Urm bash -c "
  mount --bind $S/resolv.conf /etc/resolv.conf
  cat /etc/resolv.conf
"
cat /etc/resolv.conf | head -1     # host untouched
```

> ⚠️ **File binds break on editor-style writes.** `vim`/`sed -i` replace the file by creating a new inode and renaming over it — the bind still points at the *old* inode, so the container never sees the change. This is exactly why Kubernetes mounts ConfigMaps as a **directory of symlinks** and atomically swaps the symlink target instead of rewriting files in place.

## **The container equivalents**

```bash
# Docker
docker run -v /host/path:/container/path:ro    myimage      # ro bind
docker run -v /host/path:/container/path:rslave myimage      # + propagation
docker run --mount type=bind,src=/host,dst=/ctr,readonly     # explicit form

# Kubernetes
```

```yaml
volumes:
  - name: host-data
    hostPath: { path: /host/path, type: Directory }
volumeMounts:
  - name: host-data
    mountPath: /container/path
    readOnly: true
    mountPropagation: HostToContainer
    subPath: only-this-dir        # ← implemented as a bind of a subdirectory
```

`subPath` is literally a bind mount of a subdirectory of the volume — and it carries the **same stale-inode caveat** as file binds above, which is why `subPath` with a ConfigMap does not pick up updates.

## **Debugging bind mounts**

```bash
findmnt -o SOURCE,TARGET,FSTYPE,OPTIONS,PROPAGATION --target /path
findmnt -no SOURCE --target /path          # the [subpath] bracket tells you it's a bind
grep ' /path ' /proc/self/mountinfo        # field 4 = root within the source fs

# is this path a mount point at all?
mountpoint /path
```

**Checklist when a bind "isn't working":**

| Check | Command |
| ----- | ------- |
| Is it actually mounted? | `mountpoint /dst` |
| Is `ro` real? | `findmnt -no OPTIONS --target /dst` |
| Are submounts missing? | you needed `--rbind` |
| Not seeing host updates? | propagation — [2.propagation.md](2.propagation.md) |
| File content stale? | inode replaced — bind the **directory**, not the file |
