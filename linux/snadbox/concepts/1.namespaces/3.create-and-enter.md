## **The `unshare` flags you will use constantly**

| Flag           | Meaning                                                                        |
| -------------- | ------------------------------------------------------------------------------ |
| `-U`           | new user namespace                                                             |
| `-r`           | map current user → root inside it (implies `-U`)                               |
| `-u`           | UTS · `-i` IPC · `-p` PID · `-n` net · `-m` mount · `-C` cgroup · `-T` time    |
| `-f`           | **fork** before `exec` — mandatory with `-p`, harmless otherwise                |
| `--mount-proc` | implies `-m`, then remounts `/proc` so `ps`/`top` reflect the new PID namespace |
| `--propagation` | mount propagation for the new mount ns (default: `private`)                   |

> **Habit worth forming:** always type `-f`. It costs nothing when unnecessary and saves a confusing debugging session when it isn't. See [../2.pid/2.fork-rule.md](../2.pid/2.fork-rule.md).

## **Demo: the smallest possible namespace**

UTS is the "hello world" — one string, trivially observable. Use it to confirm your kernel is ready before moving on.

```bash
unshare -Ur --fork --uts sh -c 'hostname sandbox; echo "inside : $(hostname)"'
echo "outside: $(hostname)"
```

```
inside : sandbox
outside: anisur-rahman-PC
```

The sandbox renamed the machine. The machine disagrees. **Both are correct** — they are reading different variables.

Run it interactively to feel it:

```bash
unshare -Ur --fork --uts bash
hostname sandbox
hostname          # sandbox
exit
hostname          # anisur-rahman-PC — nothing was ever changed on the host
```

## **Demo: namespaces compose**

Ask for several at once and you have a container shell:

```bash
unshare -Ur --fork --uts --ipc --pid --mount --net --mount-proc bash
```

Inside, check what you got:

```bash
hostname sandbox && hostname     # own UTS
echo $$                          # 1 — own PID namespace
ps ax | wc -l                    # tiny — own /proc
ip link                          # only a down loopback — own network
findmnt | wc -l                  # own mount table
```

That single command is ~90% of what `docker run` does. What's missing is the root filesystem ([../3.mount/](../3.mount/)) and the resource limits ([../4.cgroup/](../4.cgroup/)).

## **Entering an existing namespace: `nsenter`**

`nsenter` is `docker exec` / `kubectl exec` minus the daemon. It works on **any** process, containerized or not.

```bash
# Terminal 1 — a long-lived sandbox
unshare -Ur --fork --uts --pid --mount-proc sleep 1000
```

```bash
# Terminal 2 — find it, confirm it differs, then walk in
PID=$(pgrep -f 'sleep 1000' | head -1)
readlink /proc/self/ns/pid /proc/$PID/ns/pid
```

```
pid:[4026531836]     ← you
pid:[4026533230]     ← the sandbox
```

```bash
nsenter --target $PID --all --preserve-credentials -- bash
```

| Flag                     | Meaning                                                      |
| ------------------------ | ------------------------------------------------------------ |
| `-t PID` / `--target`    | Take namespaces from this process                            |
| `-a` / `--all`           | Enter every namespace it has                                 |
| `-u -i -p -m -n -C -U`   | Enter only the listed types (same letters as `unshare`)      |
| `--preserve-credentials` | Don't `setuid` — **required** when entering a user namespace |
| `-r` / `--root`          | Also `chroot` into the target's root                         |
| `-w` / `--wd`            | Also switch to the target's cwd                              |

### The surgical form is usually more useful

Borrow exactly one view and keep your own tools — invaluable when the target has no shell:

```bash
nsenter -t $PID -n -- ss -tulpn     # its network, your binaries
nsenter -t $PID -m -- df -h         # its mounts, your binaries
nsenter -t $PID -u -- hostname      # its hostname
```

> ⚠️ **Gotcha:** after `nsenter --pid`, your *shell* is still in the old PID namespace — PID namespaces only apply to children. Only processes you spawn afterwards get sandbox PIDs. Verify with `readlink /proc/self/ns/pid_for_children`.

## **Reading a container without entering it**

`/proc/PID/root` is a magic symlink to that process's filesystem root. You can read straight through it from the host:

```bash
sudo ls  /proc/$PID/root/etc/
sudo cat /proc/$PID/root/var/log/app.log
sudo cat /proc/$PID/cmdline | tr '\0' ' '; echo
sudo ls -l /proc/$PID/cwd /proc/$PID/exe
sudo ls   /proc/$PID/fd
```

This is the fastest way to pull a file out of a distroless container that has no shell to `exec` into.

## **Real-world equivalents**

```bash
# Docker
PID=$(docker inspect -f '{{.State.Pid}}' <container>)

# containerd / Kubernetes node
PID=$(sudo crictl inspect <container-id> | jq .info.pid)

# then, in both cases:
sudo nsenter -t $PID -n -- ss -tulpn       # debug its networking with host tools
sudo nsenter -t $PID -m -- mount           # see its mount table
sudo ls /proc/$PID/root/                   # browse its filesystem
```
