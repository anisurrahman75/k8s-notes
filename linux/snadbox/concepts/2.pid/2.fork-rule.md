# **2. Why `--fork` Is Mandatory**

← [1.first-namespace.md](1.first-namespace.md) | next → [3.mount-proc.md](3.mount-proc.md)

---

## **The rule**

> `unshare(CLONE_NEWPID)` **does not move the calling process into the new namespace.**

The caller's PID is already assigned and immutable. What the syscall actually means is:

*"the next child I `fork()` will be PID 1 of a new namespace."*

So without `--fork`, `unshare` creates the namespace and then `exec`s your command **in the old namespace** — pointing at a namespace it isn't a member of.

---

## **Demo: the failure**

```bash
unshare -Urp --mount-proc bash -c 'echo hi'
```

```
unshare: mount /proc failed: Operation not permitted
```

The error looks like it's about `/proc`, which sends people down the wrong path. It isn't. `unshare` is trying to mount procfs *for a PID namespace it is not in*, and the kernel refuses. Add `-f` and it works instantly:

```bash
unshare -Urpf --mount-proc bash -c 'echo "hi from PID $$"'
```

```
hi from PID 1
```

---

## **Demo: watch the split**

The `unshare` wrapper stays behind in the host namespace; only its child crosses over.

```bash
unshare -Urpf --mount-proc sleep 40 &
UPID=$!; sleep 1

echo "wrapper pid = $UPID"
readlink /proc/$UPID/ns/pid /proc/$UPID/ns/pid_for_children

CHILD=$(pgrep -P $UPID)
echo "child pid   = $CHILD"
readlink /proc/$CHILD/ns/pid
```

```
wrapper pid = 428105
pid:[4026531836]      ← wrapper's own pid ns   = HOST
pid:[4026536054]      ← wrapper's pid_for_children = the NEW ns
child pid   = 428107
pid:[4026536054]      ← the child IS in the new ns
```

Three symlinks, one story:

| Process | `ns/pid` | `ns/pid_for_children` |
| ------- | -------- | --------------------- |
| wrapper | host     | **new**               |
| child   | **new**  | new                   |

`pid_for_children` is the kernel telling you "there's a pending namespace here that will apply at the next fork". That is the entire mechanism.

---

## **Confirm the child really is PID 1**

```bash
grep NSpid /proc/$CHILD/status
lsns -t pid -p $CHILD
```

```
NSpid:	428107	1

        NS TYPE NPROCS    PID USER   COMMAND
4026536054 pid       1 428107 anisur sleep 40
```

One process, two names: **host PID 428107 = namespace PID 1**. More on this in [6.debugging.md](6.debugging.md).

```bash
kill $UPID     # cleanup
```

---

## **Why real runtimes don't have this problem**

`runc` and friends never call `unshare()` for PID. They call:

```c
clone(child_fn, stack, CLONE_NEWPID | CLONE_NEWNS | CLONE_NEWUTS | ... , arg);
```

The child is **born** inside the namespace — atomic, no intermediate state, no wrapper left behind. `unshare` is a two-step tool (`unshare()` then `execve()`), and `--fork` is how it papers over the gap.

---

## **Takeaway**

> **`-p` without `-f` is always a bug.** Make `-pf` a single muscle-memory token.

And note `-f` is harmless for every other namespace type — UTS, IPC, mount, net all apply to the calling process immediately. Typing it always costs nothing.
