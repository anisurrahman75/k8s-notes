## **`systemd-run` — transient cgroups**

```bash
systemd-run --user --scope \
  -p MemoryMax=100M \
  -p MemoryHigh=80M \
  -p CPUQuota=50% \
  -p TasksMax=100 \
  -- bash
```

Inside, verify the kernel actually got them:

```bash
CG=/sys/fs/cgroup$(cut -d: -f3 /proc/self/cgroup)
echo $CG
cat $CG/memory.max $CG/memory.high $CG/cpu.max $CG/pids.max
```

```
/sys/fs/cgroup/user.slice/user-1000.slice/user@1000.service/app.slice/run-rf322....scope
104857600
83886080
50000 100000
100
```

**The translation table:**

| systemd property | cgroup v2 file | Value written |
| ---------------- | -------------- | ------------- |
| `MemoryMax=100M` | `memory.max` | `104857600` |
| `MemoryHigh=80M` | `memory.high` | `83886080` |
| `MemorySwapMax=0` | `memory.swap.max` | `0` |
| `CPUQuota=50%` | `cpu.max` | `50000 100000` |
| `CPUWeight=200` | `cpu.weight` | `200` |
| `TasksMax=100` | `pids.max` | `100` |
| `IOWeight=50` | `io.weight` | `50` |

| Flag | Meaning |
| ---- | ------- |
| `--user` | your session's tree — no sudo |
| `--scope` | run **here**, in this terminal, synchronously |
| `--unit=NAME` | name it so you can find it later |
| *(no `--scope`)* | run as a background transient **service** instead |

```bash
systemd-run --user --unit=mytask -p MemoryMax=50M --  sleep 300   # background service
systemctl --user status mytask
systemd-cgls --user                                                # the tree
systemd-cgtop                                                      # live top, per cgroup
systemctl --user stop mytask                                       # cleans the cgroup
```

**Change limits on a running unit:**

```bash
systemctl --user set-property mytask MemoryMax=200M
```

## **Docker**

```bash
docker run -d --name demo \
  --memory 100m --memory-swap 100m \
  --cpus 0.5 \
  --pids-limit 100 \
  alpine sleep 300
```

**Find and read its actual cgroup:**

```bash
PID=$(docker inspect -f '{{.State.Pid}}' demo)
CG=/sys/fs/cgroup$(sudo cat /proc/$PID/cgroup | cut -d: -f3)
cat $CG/memory.max $CG/cpu.max $CG/pids.max
```

```
104857600
50000 100000
100
```

| Docker flag | cgroup file |
| ----------- | ----------- |
| `--memory 100m` | `memory.max` |
| `--memory-swap 100m` | `memory.swap.max` = swap total − memory |
| `--memory-reservation` | `memory.low` |
| `--cpus 0.5` | `cpu.max = 50000 100000` |
| `--cpu-shares 512` | `cpu.weight` (rescaled) |
| `--cpuset-cpus 0-3` | `cpuset.cpus` |
| `--pids-limit 100` | `pids.max` |
| `--blkio-weight` | `io.weight` |

```bash
docker stats demo         # reads memory.current / cpu.stat under the hood
docker rm -f demo
```

## **Kubernetes**

```yaml
resources:
  requests:                 # scheduling + share under contention
    memory: "256Mi"         # -> memory.min / memory.low (protection)
    cpu: "100m"             # -> cpu.weight ≈ 4
  limits:                   # hard ceilings
    memory: "512Mi"         # -> memory.max = 536870912
    cpu: "500m"             # -> cpu.max = "50000 100000"
```

**QoS classes**, which decide who dies first under node pressure:

| Class | Condition | Under node memory pressure |
| ----- | --------- | -------------------------- |
| `Guaranteed` | requests == limits, for every container | evicted last |
| `Burstable` | requests < limits | evicted second |
| `BestEffort` | neither set | **evicted first** |

**The node's cgroup tree:**

```
/sys/fs/cgroup/kubepods.slice/
├── kubepods-besteffort.slice/
├── kubepods-burstable.slice/
│   └── kubepods-burstable-pod<uid>.slice/
│       ├── cri-containerd-<pause-id>.scope
│       └── cri-containerd-<app-id>.scope    ← your container
└── (Guaranteed pods sit directly under kubepods.slice)
```

**Node-side debugging recipe:**

```bash
PID=$(sudo crictl inspect <container-id> | jq .info.pid)
CG=/sys/fs/cgroup$(sudo cat /proc/$PID/cgroup | cut -d: -f3)

cat $CG/memory.max $CG/memory.current $CG/memory.events   # OOM story
cat $CG/cpu.max $CG/cpu.stat                              # throttling story
cat $CG/pids.max $CG/pids.current                         # fork story
cat $CG/memory.pressure $CG/cpu.pressure                  # PSI — the early warning
```

## **Symptom → file cheat sheet**

| Symptom | Check | Meaning |
| ------- | ----- | ------- |
| Exit code **137**, `OOMKilled` | `memory.events` → `oom_kill` | hit `memory.max` |
| Slow, but CPU usage looks low | `cpu.stat` → `nr_throttled/nr_periods` | hit `cpu.max` |
| `fork: Resource temporarily unavailable` | `pids.current` vs `pids.max` | hit `pids.max` |
| Gradual slowdown, no kills | `memory.events` → `high` climbing | hitting `memory.high` |
| Everything is slow, limits look fine | `cpu.pressure`, `memory.pressure` | contention from **neighbours** |
| Pod evicted, container never OOMed | node-level pressure | QoS class — likely BestEffort |

## **Legacy: cgroup v1**

You will still meet v1 on older nodes.

```bash
stat -fc %T /sys/fs/cgroup
```

| Output | Version |
| ------ | ------- |
| `cgroup2fs` | v2 (everything in this folder) |
| `tmpfs` | v1 or hybrid |

| v2 | v1 equivalent |
| -- | ------------- |
| `memory.max` | `memory/memory.limit_in_bytes` |
| `memory.current` | `memory/memory.usage_in_bytes` |
| `cpu.max` | `cpu/cpu.cfs_quota_us` + `cpu.cfs_period_us` |
| `cpu.weight` | `cpu/cpu.shares` |
| `pids.max` | `pids/pids.max` |
| one unified tree | one tree **per controller** |

v1 has no PSI, no `cgroup.kill`, no `memory.high`, and no delegation model — which is why rootless containers effectively require v2.
