# **5. Building a Root Filesystem**

← [4.overlayfs.md](4.overlayfs.md) | next → [6.pivot-root.md](6.pivot-root.md)

---

A rootfs is not magic. It is **a directory containing the files a program expects to find at `/`**. Three ways to get one, cheapest first.

---

## **Option A: busybox (2 MB, zero dependencies)**

`busybox` is a single **statically linked** binary implementing ~400 UNIX commands. Static matters enormously — no `ld.so`, no `/lib`, nothing to copy.

```bash
file $(command -v busybox)
```

```
ELF 64-bit LSB executable, x86-64, statically linked, stripped
```

### Build it

```bash
ROOTFS=/tmp/nslab/rootfs
mkdir -p $ROOTFS/{bin,proc,sys,dev,tmp,etc,oldroot}
cp $(command -v busybox) $ROOTFS/bin/

# applet symlinks — MUST be relative, see the gotcha below
( cd $ROOTFS/bin && for a in $(./busybox --list); do ln -sf busybox "$a"; done )

ls $ROOTFS/bin | wc -l
```

```
272
```

### ⚠️ The symlink gotcha

`busybox --install -s` looks convenient and is a trap:

```bash
busybox --install -s $ROOTFS/bin/
ls -l $ROOTFS/bin/mount
```

```
mount -> /tmp/nslab/rootfs/bin/busybox      ← ABSOLUTE host path
```

After `pivot_root`, `/tmp/nslab/rootfs/bin/busybox` does not exist any more, and every command breaks:

```
sh: mount: not found
sh: ls: not found
```

The manual loop above creates `mount -> busybox` — **relative**, so it resolves inside the new root. Always check:

```bash
ls -l $ROOTFS/bin/mount
```

```
mount -> busybox
```

### Minimal `/etc`

```bash
cat > $ROOTFS/etc/passwd <<'EOF'
root:x:0:0:root:/:/bin/sh
EOF
cat > $ROOTFS/etc/group <<'EOF'
root:x:0:
EOF
echo "sandbox" > $ROOTFS/etc/hostname
echo "nameserver 1.1.1.1" > $ROOTFS/etc/resolv.conf
```

## **Option B: steal one from a container image**

The fastest way to get a *real* distro rootfs, and it needs no `debootstrap`:

```bash
ROOTFS=/tmp/nslab/alpine
mkdir -p $ROOTFS

CID=$(docker create alpine:latest)
docker export $CID | tar -C $ROOTFS -xf -
docker rm $CID

ls $ROOTFS
```

```
bin  dev  etc  home  lib  media  mnt  opt  proc  root  run  sbin  srv  sys  tmp  usr  var
```

`docker export` flattens all overlay layers into one tarball — exactly the "merged" view from [4.overlayfs.md](4.overlayfs.md).

**Without Docker at all**, straight from a registry:

```bash
curl -sL https://dl-cdn.alpinelinux.org/alpine/v3.20/releases/x86_64/alpine-minirootfs-3.20.0-x86_64.tar.gz \
  | tar -C $ROOTFS -xzf -
```

> ⚠️ Extracting as a normal user drops setuid bits and remaps ownership to you. Fine for a sandbox; not fine for building images to ship. Rootless tooling handles this with `unshare -Ur tar ...` inside the userns so the UIDs land in your mapped range.

---

## **Option C: a full Debian/Ubuntu rootfs**

```bash
sudo apt install debootstrap
sudo debootstrap --variant=minbase noble /tmp/nslab/ubuntu http://archive.ubuntu.com/ubuntu/
```

Slow (hundreds of MB) but gives you a genuine, package-manageable system. This is what LXC and `systemd-nspawn` templates use.

## **What a rootfs still needs at runtime**

The directory alone isn't enough — these must be mounted *after* you enter it ([6.pivot-root.md](6.pivot-root.md)):

| Mount | Command | Why |
| ----- | ------- | --- |
| `/proc` | `mount -t proc proc /proc` | `ps`, `top`, `/proc/self` |
| `/sys` | `mount -t sysfs sys /sys` | device/kernel info |
| `/dev` | `mount -t tmpfs dev /dev` + nodes | `/dev/null`, `/dev/urandom` |
| `/dev/pts` | `mount -t devpts devpts /dev/pts` | terminals |
| `/tmp` | `mount -t tmpfs tmp /tmp` | scratch space |

**Minimal `/dev` rootless.** You cannot `mknod` in a user namespace, so you bind-mount the host's nodes instead. There is a sharp gotcha here — verified on kernel 6.17:

```bash
# ❌ target on a tmpfs YOU mounted inside the userns: reads work, WRITES are denied
mount -t tmpfs tmpfs /dev
touch /dev/null && mount --bind /oldroot/dev/null /dev/null
echo hi > /dev/null
```

```
sh: can't create /dev/null: Permission denied
```

```bash
# ✅ recursively bind the host's whole /dev
mount --rbind /oldroot/dev /dev
echo hi > /dev/null && echo "WRITE OK"
```

```
crw-rw-rw-  1 65534 65534  1, 3 /dev/null       ← owner is unmapped (nobody), but usable
WRITE OK
```

Binding an individual node onto a file on a *namespace-created* tmpfs yields a node you can read but not write; binding onto a target on an inherited filesystem, or `--rbind`-ing the whole directory, works. If you hit `Permission denied` writing to `/dev/null` in a rootless sandbox, this is why.

> ⚠️ `--rbind /dev` exposes **everything** the host has — including `/dev/sda`. For a real sandbox, bind the short list onto the rootfs's own `/dev` directory (not a fresh tmpfs), or use `bwrap --dev /dev` which handles this correctly:
>
> ```bash
> bwrap --ro-bind $ROOTFS / --dev /dev --proc /proc /bin/busybox sh
> ```

Docker creates exactly this short list — `null`, `zero`, `full`, `random`, `urandom`, `tty`, plus `/dev/console`, `/dev/pts`, `/dev/shm` — and nothing else. **No `/dev/sda`.** A container with `/dev/sda` in its rootfs can read the raw host disk regardless of every namespace you set up.

## **Dynamic binaries need their libraries**

If your rootfs is busybox-only and you copy in a host binary, it will fail with a useless error:

```bash
cp /bin/ls $ROOTFS/bin/
# inside: sh: /bin/ls: not found     ← the LOADER is missing, not ls
```

Copy the interpreter and every shared object:

```bash
ldd /bin/ls
```

```
	linux-vdso.so.1
	libselinux.so.1 => /lib/x86_64-linux-gnu/libselinux.so.1
	libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6
	/lib64/ld-linux-x86-64.so.2
```

```bash
mkdir -p $ROOTFS/lib/x86_64-linux-gnu $ROOTFS/lib64
for lib in $(ldd /bin/ls | grep -o '/[^ ]*\.so[^ ]*'); do
  cp -L "$lib" "$ROOTFS$lib" 2>/dev/null || cp -L "$lib" "$ROOTFS/lib64/"
done
```

> 💡 **`sh: not found` when the file clearly exists = missing dynamic loader.** This is the single most common confusion when hand-building a rootfs — and the reason "distroless" and "scratch" images ship static binaries.

## **Verify before you pivot**

```bash
ROOTFS=/tmp/nslab/rootfs
ls -l $ROOTFS/bin/sh                                  # relative symlink?
[ -d $ROOTFS/proc ] && [ -d $ROOTFS/oldroot ] && echo "mount points ok"
chroot $ROOTFS /bin/busybox echo "rootfs works"       # quick smoke test (needs root/userns)
```
