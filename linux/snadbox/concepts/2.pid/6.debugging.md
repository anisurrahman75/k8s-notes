## **One process, many PIDs**

A process belongs to its own namespace **and every ancestor**, with a different PID in each. `/proc/PID/status` shows the whole chain:

```bash
unshare -Urpf --mount-proc sleep 40 &
sleep 1; CHILD=$(pgrep -P $!)
grep -E 'NSpid|NStgid' /proc/$CHILD/status
```

```
NStgid:	428107	1
NSpid:	428107	1
```

Read **left → right = outermost → innermost**:

```
  428107   →   1
  host PID     namespace PID
```

A single process with two names. With nesting you get three columns, four, and so on.

> 🔑 `NSpid` is the Rosetta stone. The container reports PID 1, the node's `ps` reports 428107, and this line connects them.

**The namespace's own view:**

```bash
lsns -t pid -p $CHILD
```

```
        NS TYPE NPROCS    PID USER   COMMAND
4026536054 pid       1 428107 anisur sleep 40
```

`lsns` always prints **host** PIDs — that's the number you feed to `nsenter`.

## **The full debugging workflow**

```bash
# 1. Start a sandbox
unshare -Ur --fork --uts --pid --mount-proc sleep 1000 &
W=$!; INIT=$(pgrep -P $W)

# 2. Host PID -> namespace PID
grep NSpid /proc/$INIT/status

# 3. Which namespaces is it in?
ls -l /proc/$INIT/ns/
lsns -p $INIT

# 4. Walk in (this is `docker exec`, by hand)
nsenter -t $INIT --pid --mount --uts --user --preserve-credentials -- ps aux

# 5. Or inspect without entering
sudo cat /proc/$INIT/cmdline | tr '\0' ' '; echo
sudo ls -l /proc/$INIT/cwd /proc/$INIT/root /proc/$INIT/exe
sudo ls /proc/$INIT/fd
```

> 💡 **`/proc/PID/root`** is a magic symlink into the process's filesystem root. `sudo ls /proc/$INIT/root/` reads files **inside** the sandbox from the host — no `nsenter`, no shell needed inside. Fastest way to pull a log out of a distroless container.

## **Real-world: Docker and Kubernetes**

```bash
# Docker
PID=$(docker inspect -f '{{.State.Pid}}' <container>)

# containerd / CRI-O on a Kubernetes node
PID=$(sudo crictl inspect <container-id> | jq .info.pid)

# then, in both cases:
sudo nsenter -t $PID -n -- ss -tulpn        # its listening sockets, using YOUR tools
sudo nsenter -t $PID -m -- df -h            # its mounts
sudo nsenter -t $PID -p -- ps aux           # its process table
sudo ls /proc/$PID/root/etc/                # its files, no exec needed
sudo cat /proc/$PID/root/var/log/app.log
```

**Why this beats `kubectl exec`:**

| | `kubectl exec` | `nsenter` from the node |
| --- | --- | --- |
| Needs a shell in the image | ✅ yes | ❌ no |
| Needs the tool in the image | ✅ yes | ❌ uses host tools |
| Works on a wedged container | ❌ often not | ✅ usually |
| Works on distroless / scratch | ❌ | ✅ |

## **Nesting: namespaces are a tree**

PID namespaces nest up to 32 levels. Each level restarts numbering at 1.

```bash
unshare -Urpf --mount-proc bash -c '
  echo "level 1: pid=$$"
  unshare -pf --mount-proc bash -c "
      echo \"level 2: pid=\$\$\"
      sleep 5 & sleep 5 &
      echo \"level 2 sees: \$(ps ax | wc -l)\"
      sleep 2" &
  sleep 1
  echo "level 1 sees: $(ps ax | wc -l)"
  wait
'
```

```
level 1: pid=1
level 2: pid=1
level 2 sees: 7      ← only its own subtree
level 1 sees: 9      ← its own processes PLUS everything in level 2
```

Both shells are PID 1 — of **different** namespaces.

**The hierarchy rule:** level 1 can `kill` level 2's processes (using level-1 PIDs); level 2 cannot even name level 1's. No sibling visibility either.

This is exactly how Docker-in-Docker, KinD nodes, and nested `systemd-nspawn` work — and why you can always debug all the way down from the physical host.

## **Quick reference**

```bash
# --- create ---
unshare -Urpf --mount-proc bash        # rootless, correct /proc
unshare -Urpfm bash                    # manual: then `mount -t proc proc /proc`
sudo unshare -pf --mount-proc bash     # as real root

# --- inspect ---
grep NSpid /proc/PID/status            # host pid <-> ns pid chain
readlink /proc/PID/ns/pid              # which namespace
readlink /proc/PID/ns/pid_for_children # what its children will get
lsns -t pid                            # all PID namespaces
lsns -t pid -p PID                     # this process's namespace
sudo lsns -T                           # nesting tree

# --- enter / read ---
nsenter -t PID --pid --mount --preserve-credentials -- ps aux
sudo ls /proc/PID/root/                # read its filesystem without entering

# --- the rules ---
#  -p ALWAYS with -f              (pid ns applies to children only)
#  -p ALWAYS with --mount-proc    (else ps shows the host)
#  PID 1 ignores unhandled SIGTERM  -> install a handler / use tini
#  PID 1 dies -> whole namespace dies
#  PID 1 must reap orphans          -> exec / tini / shareProcessNamespace
```
